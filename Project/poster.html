Abstract

Linux Process Lifecycle System is a high-performance Linux kernel and POSIX systems programming utility engineered in C for Ubuntu/Linux. It delivers a comprehensive platform featuring both a native ANSI-colored terminal CLI and a zero-dependency interactive Web visualizer for operating systems students, developers, and educators. The system implements and inspects the complete process lifecycle through standard POSIX APIs (fork(), execvp(), waitpid(), exit()) while extracting real-time Process Control Block (PCB) telemetry directly from the kernel virtual filesystem (/proc/<pid>/status).

Key Outcome: Achieved 100% deterministic process management across 6 verified scenarios, successfully trapping and observing pathological Zombie (Z) and Orphan (PID 1 init) states with live /proc telemetry and zero runtime overhead.

Problem Statement & Objectives

Problem: Process management is the foundation of operating systems, yet textbook abstractions fail to illustrate dynamic kernel-level mechanisms—such as Copy-On-Write (COW) memory page cloning, virtual address space replacement via exec(), Zombie accumulation in the kernel process table, and Orphan reparenting—leaving students with a fragmented theoretical understanding.

Objective 1: Implement a modular C systems engine on the Linux kernel demonstrating process cloning via fork() and binary execution via execvp() with Copy-On-Write memory tracking.

Objective 2: Implement robust parent-child synchronization and non-blocking monitoring using wait() and waitpid() with the WNOHANG flag to prevent process deadlocks.

Objective 3: Build a real-time kernel inspector querying /proc/<pid>/status to observe live execution states (R, S, Z) and decode termination status via POSIX macros.

Objective 4: Provide a dual-interface telemetry pipeline: ANSI color-coded terminal logging and an interactive web visualizer with zero external npm dependencies.

Scope: Targets Ubuntu 24.04 LTS (WSL2 / Linux Kernel 6.18+); strictly unprivileged user-space operation; covers full lifecycle, anomaly trapping, and automated test matrix.

Process, IPC & Resource Design
A. Lifecycle & State Transitions
• Creation: fork() clones parent PCB via Copy-On-Write; child receives 0, parent receives child PID.
• Execution: execvp() replaces address space (Text, Data, Heap, Stack) with target binary.
• Termination: exit() releases virtual memory, leaving task_struct for status reading.
NEW ➔ READY ➔ RUNNING ➔ ZOMBIE ➔ REAPED
B. Synchronization & /proc Inspector
• Non-blocking: waitpid(WNOHANG) polling loop enables concurrent parent background computation.
• Zombie Trapping: Child calls exit(42); parent delays wait(); /proc/<pid> confirms State: Z (zombie).
• Orphan Adoption: Parent exits prematurely; kernel automatically reparents child to PID 1 (init).
• Status Decoding: WIFEXITED & WIFSIGNALED accurately decode codes and signals.
